# Validation command security

`weave integrate -- <command> [args...]` executes the requested program directly, with the user's operating-system permissions, in a disposable checkout. Only run trusted commands and trust the code they execute. Validation can read and modify files accessible to the user and use the network; a disposable checkout is not a security sandbox. A command can override its Git environment and access other repositories. Validation output is returned to the caller.

By default, Weave clears the inherited environment and supplies only `PATH`, a temporary `HOME`, `LANG`, `LC_ALL`, and `LC_CTYPE` when present, plus Git variables that direct cooperative Git commands to the disposable repository and disable hooks and fsmonitor. This reduces accidental exposure of parent environment variables but does not protect secrets stored on disk or prevent network access. The inherited `PATH` controls executable lookup and must be trusted. Configurations and caches in the user's home are not automatically available. For example, a rustup proxy may need an explicit `PATH` to an installed toolchain's `bin` directory to run `cargo test`.

There is no network isolation. Linux network namespaces could provide a boundary when the host permits the required namespaces and capabilities, but availability varies with system policy; they require careful fail-closed setup. macOS App Sandbox can restrict networking for sandboxed signed applications and directly launched helpers, but is not a drop-in portable per-command sandbox for this CLI. Neither approach is implemented by Weave. See [Linux namespaces](https://man7.org/linux/man-pages/man7/namespaces.7.html), [network namespaces](https://man7.org/linux/man-pages/man7/network_namespaces.7.html), and [Apple's App Sandbox documentation](https://developer.apple.com/documentation/security/discovering-and-diagnosing-app-sandbox-violations).

Any future MCP interface must require human confirmation before it can set or change a validation command. This is a design constraint, not an implemented MCP feature.

Use repeatable `--pass-env NAME` only for values the validation command should receive. Values come from the parent environment; unset or invalid names, `HOME`, and `GIT_*` are rejected to retain the temporary home and Git protections. Passing a variable may expose its value to the command and its children. For rustup, set and explicitly pass `CARGO_HOME` and `RUSTUP_HOME`.
